-----------------------------------------------------
GOAL
-----------------------------------------------------
Build the sign-up and log-in step of a website, the safe way: the
password is never stored. Then look inside to see why it's safe, and
how the dict that holds the users finds them so fast.

-----------------------------------------------------
WHAT IT PRACTISES
-----------------------------------------------------
salted hashing     -> os.urandom(16) for the salt, and
                      hashlib.pbkdf2_hmac("sha256", ...) for the hash
                      (understanding_hash.ipynb, the hashlib section)
hash table (dict)  -> users = {username: {"salt": ..., "hash": ...}}
                      users.get(name, default) for a safe lookup
dict instead of if -> {True: "Login successful", False: "Invalid ..."}
                      then messages[login_ok]
hash()             -> hash(username) % 8 picks a bucket; string
                      hashes change every run (hash randomization)
`in` on dict / set -> one lookup, however many items there are
bytes and hex      -> .encode(), .hex(), bytes.fromhex()

-----------------------------------------------------
REQUIREMENTS
-----------------------------------------------------
1. Step 1, sign up: ask for a username and a password. Usernames
   ignore case and surrounding spaces ("  Bala" = "bala").
2. Store only a random salt and the salted hash, as hex text, in a
   dict keyed by username. Show the saved record and its fields.
3. Step 2, log in: ask again, hash the attempt with the SAME salt, and
   compare. A wrong password and an unknown username must give the
   same message, so nobody can find out which usernames exist.
4. Step 3: show that the same password with a new salt gives a
   different hash, and print the unsalted SHA-256 for comparison.
5. Step 4: show the username's hash(), its bucket in an 8-bucket
   table, and `in` lookups on the users dict and a set of reserved
   names.
