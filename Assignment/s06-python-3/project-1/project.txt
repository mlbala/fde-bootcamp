The custom exceptions need one line each, like
    class InsufficientFundsError(ATMError): ...
That's how 01_exception_handling.ipynb defines its custom exception.
Writing real classes, with attributes and methods, is project 3.
There are no files yet, so the accounts are kept in a dict in memory
and start fresh every time the program runs.

-----------------------------------------------------
GOAL
-----------------------------------------------------
Build the software of a cash machine: insert a card, enter the PIN,
check the balance, deposit, withdraw, see a mini statement and change
the PIN. A real ATM must never crash, whatever the customer types, so
every rule is an exception that the menu catches and explains.

-----------------------------------------------------
WHAT IT PRACTISES
-----------------------------------------------------
try / except       -> float("abc") raises ValueError: catch it
specific excepts   -> catch WrongPinError (ask again) separately from
                      CardBlockedError (end the visit)
except order       -> CardBlockedError BEFORE ATMError, because the
                      first matching except wins
turning one error  -> a KeyError from accounts[number] becomes an
into another          AccountNotFoundError ("raise ... from None")
raise              -> the bank's rules: not enough money, over the
                      daily limit, not a multiple of 100, ...
custom exceptions  -> a family tree with one base class:
                          ATMError
                          |-- AccountNotFoundError
                          |-- WrongPinError
                          |-- CardBlockedError
                          |-- InvalidAmountError
                          |-- InsufficientFundsError
                          |-- DailyLimitError
                          `-- InvalidPinError
                      so "except ATMError" catches them all
else               -> "Welcome!" only when check_pin() raised nothing
finally            -> "Please take your card." however the visit ends,
                      even with Ctrl + C
travelling up      -> change_pin() calls check_pin(); a wrong PIN
                      raised deep inside reaches the menu's except

-----------------------------------------------------
REQUIREMENTS
-----------------------------------------------------
1. "Insert card? (y/n)" starts a visit; "n" switches the ATM off.
2. Two demo accounts: 1001 (Bala, PIN 1234, Rs 15,000) and
   1002 (Kumar, PIN 4321, Rs 2,500).
3. Unknown account number -> AccountNotFoundError, visit ends.
4. Wrong PIN -> WrongPinError, "2 tries left", ask again. After 3
   wrong PINs in a row the card is blocked (CardBlockedError), even
   for the right PIN. A correct PIN resets the count.
5. Menu: 1. Check balance  2. Deposit  3. Withdraw  4. Mini statement
         5. Change PIN     6. Take card
6. Amounts: "1,500" is accepted. Not a number, zero, negative, "nan",
   "inf" or more than 2 decimal places -> InvalidAmountError.
7. Deposit: at most Rs 50,000 at a time.
8. Withdraw: a multiple of Rs 100, not more than the balance
   (InsufficientFundsError), and at most Rs 20,000 a day in total
   (DailyLimitError, which says how much is left).
9. A failed deposit or withdrawal must not change the balance.
10. Mini statement: the last 5 transactions and the balance.
11. Change PIN: the current PIN, then the new 4-digit PIN twice; it
    must be different from the old one.
12. The program never shows a traceback: every error becomes a
    message, and the menu carries on.
